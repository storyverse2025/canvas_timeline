# AI视频剧本提示词生成

## Purpose

教会 AI 助手把模糊创意转成可拍摄、可视化、可迭代的 AI 漫剧、短片和视频剧本提示词。

**核心观点：LLM 不是一次性出稿机器，而是目前最容易获得的创作老师和搭档。**创作者要像导演和主编一样提出方向、判断质量、反复修改。不要只输入“帮我写个剧本”，要先建立清晰框架，再逐步扩写、审稿和迭代。是的，别把法拉利当共享单车骑。

## When to Apply

当用户需要以下任一内容时使用：

- AI 漫剧、AI 短片、短视频、短剧、短漫剧剧本
- 分镜、镜头表、视频生成提示词、Seedance 提示词
- 角色设定、角色小传、人物关系、对白风格
- 世界观、场景设定、旁白、故事大纲
- 把剧本转成图像/视频工具可执行的镜头提示词
- 对已有创意、剧本、分镜进行审稿、挑刺、重写、优化

## Core Techniques

1. **把 LLM 当创作搭档**  
   不要只让模型“一次出稿”，而是让它像编剧、导演、制片人、反对者一样参与创作、审稿和修改。

2. **先框架，后细节**  
   先明确题材、风格、角色、目标、背景、限制、输出格式、负面要求，再生成剧本。

3. **一次只做一件事**  
   复杂项目拆成：**世界观 → 核心冲突 → 人物小传 → 故事大纲 → 场景设计 → 台词 → 完整剧本 → 分镜提示词**。

4. **结构化提示词**  
   使用 Markdown 标题、项目符号或 XML 标签区分角色设定、世界观、任务、限制和输出格式。

5. **关键信息放开头和结尾**  
   为避免 Lost in the Middle，最重要的设定、禁止项、输出格式要在提示词开头和结尾重复。

6. **Few-shot 喂样**  
   给模型参考台词、对白节奏、画风描述或已有片段，让它模仿目标风格。

7. **多方案择优**  
   要求模型先给 3-5 个方案，再说明优劣，选择最强方案扩写。

8. **自评和交叉审稿**  
   让模型按逻辑、冲突、人物动机、画面感、可拍摄性打分并修改；必要时换模型复查。

9. **Seedance 模式决策**  
   先判断 Seedance 模式，不要机械套模板：
   - `t2v`：纯文本生成视频；适合没有参考图、重在创意、场景、动作和镜头语言。
   - `first_frame`：用一张图控制视频第一帧；适合已有明确开场构图、角色站位、场景质感。
   - `start_end_frames`：用首尾两张图控制变化；适合转场、变身、前后状态变化、镜头从 A 到 B。
   - `character_reference`：用角色参考保持人物一致；适合多镜头、多集、同一角色反复出现。

   **不要默认所有带图任务都是 first_frame**。先判断核心需求是“起始画面”“首尾变化”还是“角色一致”。

## Step-by-Step Rules

1. **先问清楚关键信息**：题材、时长、受众、平台、风格、角色数量、故事目标、禁忌内容。  
   如果用户只给一句模糊需求，先输出一版“最小可用澄清清单”，不要直接长篇出稿。

2. **用 CRT 搭建基础**：
   - Character：角色是谁？
   - Role/Goal：目标是什么？
   - Territory/Context：背景和限制是什么？

3. **用 5W1H 补全**：谁、何时、何地、做什么、为什么、怎么做。

4. **先生成一句话故事核心**，再生成三幕式或起承转合大纲。

5. **每个角色生成简短人设卡**：姓名、年龄、外貌关键词、性格、欲望、恐惧、口头禅、声音气质。

6. **每场戏必须包含**：场景、人物目标、冲突、情绪变化、视觉重点、结尾钩子。

7. **写 AI 视频剧本时提前加入导演思维**：构图、镜头运动、景别、光线、动作、场景价值、可拍摄性、可拆镜头性。

8. **生成长稿前，要求模型复述关键设定并等待确认**。

9. **长对话接近上限时，压缩成“项目档案”**，用于下一轮续写。项目档案至少包含：核心故事、世界观、角色卡、视觉风格、对白规则、禁忌、已定镜头/场景、未解决问题。

10. **发现跑偏时，强制重置准则**：  
    “忽略上一版错误设定，以下列设定为唯一准则。请先复述关键设定，再继续。”

## AI Video Script Output Checklist

输出 AI 视频剧本时，至少包含：

1. 一句话故事核心
2. 三幕式 / 起承转合大纲
3. 主要角色人设卡
4. 5 个高画面价值场景
5. 场景剧本：场景、动作、对白、镜头建议
6. 分镜提示词：景别、构图、镜头运动、光线、动作、情绪
7. Seedance 模式判断与理由
8. 负面要求
9. 自评分：逻辑、冲突、人物动机、画面感、可拍摄性
10. 下一轮修改建议

## Common Mistakes to Avoid

- 只写“帮我写个剧本”。应提供题材、角色、风格、目标、限制和格式。
- 一次塞太多任务。拆成多个小任务逐步完成。
- 不设负面要求。提前写明不要网络梗、不要旁白过多、不要角色超员等。
- 迷信一次输出。10 到 30 轮修改是正常流程。
- 不保存提示词。高质量提示词应作为资产复用。
- 长对话不压缩。及时生成项目档案，避免上下文污染。
- 只写故事不考虑画面。AI 视频剧本必须可拍、可视化、可拆成镜头。
- 默认用 `first_frame`。Seedance 模式要按控制目标选择。

## Role-Based Review Loop

复杂项目按以下角色轮流审稿：

1. **编剧**：检查核心冲突、人物欲望、转折、结尾钩子。
2. **导演**：检查画面价值、镜头调度、动作可见性、场景是否可拍。
3. **制片人**：检查角色数量、场景成本、时长、平台适配。
4. **反对者**：挑出俗套、逻辑漏洞、动机不足、信息过载。
5. **主编**：整合修改，输出下一版。

每轮都要给出：问题列表 → 修改策略 → 新版本 → 自评分。

## Project Archive Compression

当上下文变长时，输出：

```markdown
# 项目档案

## 不可更改设定

## 世界观

## 角色卡

## 视觉风格

## 对白/旁白规则

## 已确认大纲

## 已确认场景/镜头

## Seedance / 图像 / 配音约束

## 禁忌与负面要求

## 下一步任务
```

下一轮开始时先粘贴项目档案，再给当前任务。别指望模型自动记得前世今生，它又不是修仙的。

## Final Reminder

重要设定、禁止项和输出格式必须放在提示词开头和结尾。复杂创作要拆开做，先框架后细节，一次只做一件事。模型输出后必须自评、挑刺、修改；Seedance 模式必须按控制目标选择，**不要默认所有带图任务都是 first_frame**。
